# Canlıya çıkış — öncelikli checklist (v1)

Aşağıdaki sıra, “önce şunu bitir, sonra şuna geç” akışına göre düzenlendi.

---

## P0 — Yayına çıkmadan (kritik)

| #   | Madde                | Ne yapılır                                                                                                                                   |
| --- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Mobil API URL**    | Release pipeline’da `API_BASE_URL=https://api....` sabitlensin; staging/prod için ayrı flavor veya CI secret; mağaza build’inde localhost kalmadığını otomatik kontrol (grep/assert). |
| 2   | **Prod env doğrulama** | `JWT_SECRET`, `DATABASE_URL`, S3 (`S3_*`), mail (SMTP/SES), isteniyorsa Firebase JSON/path — deploy öncesi script veya health ile “eksik env = deploy fail”. |
| 3   | **DB migrasyon**     | Prod’da `migrate deploy` tek kanaldan (CI veya entrypoint); eşzamanlı iki deploy için strateji (tek migration job veya sıra kilidi bilinci). |
| 4   | **HTTPS**            | Mobil ve admin sadece TLS; WebSocket `wss://`; sertifika yenileme (LB veya cert-manager) tanımlı olsun.                                       |

---

## P1 — İlk canlı hafta (kullanıcı + güvenlik)

| #   | Madde              | Ne yapılır                                                                                                                                 |
| --- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 5   | **Login / auth throttle** | `@nestjs/throttler` veya reverse proxy rate limit: `/auth/login`, `/auth/register`, şifre sıfırlama endpoint’leri için IP başına kısıt. |
| 6   | **CORS**           | Prod’da whitelist: mobil app scheme + admin origin; `origin: true` yerine liste.                                                           |
| 7   | **Admin yüzeyi**   | `/admin-panel` için IP allowlist, VPN veya basic auth katmanı (reverse proxy); admin hesaplarında güçlü şifre / MFA politikası.               |
| 8   | **Log seviyesi**   | Prod’da her isteği `log` etmeyi kapat veya örnekleme; yapılandırılmış log + request ID; PII içeren alanları maskeleme.                       |

---

## P2 — Ölçek hazırlığı (trafik / ikinci sunucu)

| #   | Madde                         | Ne yapılır                                                                                                                                 |
| --- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 9   | **WebSocket çoklu instance** | Karar: **sticky sessions** (aynı kullanıcı aynı node) **veya** Socket.IO **Redis adapter** + aynı Redis’e bağlı tüm API pod’ları. Tek başına LB yetmez. |
| 10  | **DB bağlantı havuzu**       | Managed DB `max_connections` ve uygulama tarafı pool limiti uyumu; gerekiyorsa PgBouncer.                                                  |
| 11  | **Yavaş sorgular**           | Prisma `log: ['query']` sadece staging; prod’da yavaş sorgu izi (APM veya postgres `log_min_duration_statement`).                           |
| 12  | **Okuma ağırlığı**           | Keşif / listeler için gerektiğinde cache veya replica okuma (ileri aşama).                                                                  |

---

## P3 — Operasyon ve dayanıklılık

| #   | Madde                       | Ne yapılır                                                                      |
| --- | --------------------------- | ------------------------------------------------------------------------------- |
| 13  | **Health checks**           | `GET /health`: process up; `GET /health/ready`: DB ping (ve istenirse Redis). LB ve orchestrator buna göre trafiği keser. |
| 14  | **Yedekleme & DR**          | Postgres otomatik snapshot + geri yükleme denemesi; S3 yaşam döngüsü / silme politikası. |
| 15  | **Maliyet uyarıları**       | DB disk, S3 çıkış, log ingest için bütçe alarmı.                               |
| 16  | **Socket.IO prod ayarları** | Ping timeout, max payload, bağlantı başına limit (DoS’a karşı).                |

---

## Önerilen sıra (özet)

Önce **P0 (URL + env + HTTPS + migrate)** bitmeden yayın açmayın. Sonra **P1 (throttle → CORS → admin erişimi → log)** ile ilk haftayı güvenli geçirin. **İkinci replika veya trafik artışı** planlanıyorsa **P2 #9**’u (sticky veya Redis) mutlaka tasarıma alın; en geç replika eklemeden önce kodlanmış olmalı. **P3** sürekli iyileştirme.

---

_Kaynak: prod hazırlık sohbeti — yanlış mobil API URL’si, tek sunucu dışına çıkınca WebSocket mimarisi, login rate limit, eksik SMTP/S3/Firebase env, yük altında DB + log/IO riskleri._
